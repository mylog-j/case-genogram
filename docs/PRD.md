# 사이트 설계도(PRD) — 한글 문장으로 만드는 사례 가계도

작성일: 2026-11-15 · 이 문서는 사이트를 고칠 때마다 다시 보는 기준이다.

## 1. 한 줄 정의
사회복지사·상담사·수련생이 사례를 한글 문장으로 적으면, 사례개념화에 쓸 가계도를 바로 그려 주는 무료 도구.

## 2. 손님 (쓰는 사람)
- 누가: 현장 사회복지사, 상담사·심리상담사, 사회복지·상담 전공 학생과 수련생 (세 부류 모두)
- 어디서 알고 오나: 검색 (예: "가계도 만들기", "사례개념화 가계도")

## 3. 손님이 궁금한 것 (쓰기 전에)
1. 내담자 정보가 안전한가 — 입력한 문장이 어딘가에 저장되거나 전송되지 않는가
2. 어떻게 쓰나 — 문장을 어떻게 쓰면 가계도가 나오는가, 예시가 있는가
3. 무료인가 — 비용과 회원가입이 필요한가
4. 결과물을 활용할 수 있나 — 표준 기호로 그려지는가, 이미지·PDF로 받아 보고서에 넣을 수 있는가

## 4. 믿게 할 증거 (실제로 있는 것만)
- 가상 사례 예시: 실제 내담자가 아닌 예시 문장과, 그 문장으로 만든 가계도를 바로 보여 준다
- 만든 사람 자격·경력: (미정 — 지금은 넣지 않음)
- 후기: (실제 후기가 생기면 넣는다. 지금은 자리만)

## 5. 누르게 할 버튼 하나
- 버튼 이름: 가계도 만들기
- 누르면: 문장 입력칸으로 이동 (예시 문장을 불러오는 작은 링크를 함께 둔다)

## 6. 페이지 구성 (위에서 아래로, 한 장)
1. 첫 화면 — 사이트 이름(큰 제목) + 한 줄 소개 + 설명 + "가계도 만들기" 버튼 + 무료·가입 없이·저장 안 함. 둘레에 메모 카드 콜라주(마우스에 살짝 반응), 아래에 가상 사례가 한 글자씩 적히며 가계도가 자라는 예시
2. 달라지는 점 — 직접 그릴 때 / 이 도구에서는 비교표(4줄) + 실무에서는 이렇게 도와요(시간 절약, 기록과 그림 일치, 사례회의·수퍼비전 자료, 판단은 실무자에게)
3. 이렇게 써요 — 문장 규칙 카드(옆으로 넘기기) + 알아듣는 낱말 모두 보기
4. 안전 안내 — 입력한 문장은 내 브라우저 안에서만 처리되고, 어디에도 저장·전송되지 않음. 실명 대신 가명을 권함
5. 가계도 만들기 — 문장 입력칸 + 골라 주세요 카드 + 못 알아들은 문장 표시 + 가계도(누르고 끌어서 직접 고치기, 되돌리기, 흑백·세대 번호·범례) + 이미지·PDF 내려받기
6. 후기 자리 (비워 둠)
7. 자주 묻는 것 (기준: McGoldrick 방식 기본, 기관 지침 우선)
8. 맨 아래 — © 2026 simricube · Web Developer + simricube 로고(링크 없음)

## 7. 문의 폼에서 받을 것
- 이번엔 문의 폼을 두지 않는다 (아래 9번 참고)
- (나중에 의견 받기 폼을 붙인다면: 이름, 연락처, 의견 한 칸, 개인정보 수집·이용 동의(필수). 사례 내용은 받지 않는다)

## 8. 정확해야 하는 사실 (사용자가 말한 그대로)
- 가격: 무료, 회원가입 없이 사용
- 시간: (미정 — 해당 없음)
- 위치: (해당 없음 — 온라인 도구)
- 연락 방법: 이번엔 없음 (11번 '다음에 할 것'으로)
- 저장: 입력한 사례 문장과 가계도는 어디에도 저장하지 않는다. 창을 닫으면 사라지고, 필요하면 이미지·PDF로 직접 내려받는다

## 9. 이번에 넣지 않을 것
- 서버 저장 (회원가입·개인정보 처리방침이 필요해 오늘 범위를 넘음)
- 브라우저 임시 저장 (이어서 쓰기)
- 회원가입·로그인
- 결제
- 문의·의견 폼과 관리자 페이지(/admin)
- 만든 사람 자격·경력 소개
- 연락 방법 (이메일·오픈채팅 등)
- AI로 자유 문장 해석 (문장이 외부로 전송되므로)

## 10. 첫 화면 한 문장 후보
1. 사례를 문장으로 적으면, 가계도가 그려집니다.
2. 한글 문장 몇 줄로 사례개념화 가계도를 완성하세요.
3. 그리지 말고 적으세요. 가계도는 바로 나옵니다.

## 11. 다음에 할 것
- **(정해 둠, 마지막 순서)** 관리자 모드(/admin, 별도 주소·비밀번호) + 처음 내려받을 때 직업 묻기(사회복지사·상담사·학생·수련생·기타 직접 입력 30자, 건너뛰기 가능) + UTM 유입 추적 + 비공개 '의견 보내기'(후기 동의 체크). 이때 안전 안내 문구를 "익명 이용 통계와 보내 주신 의견만 받아요"로 고치고, 개인정보 처리 안내를 붙인다
- 브라우저 임시 저장(같은 컴퓨터에서 이어서 쓰기, 공용 PC 주의 안내 포함)
- 실제 사용 후기 넣기 (의견 보내기에서 후기 동의한 글 중 골라서)
- 만든 사람 소개, 로고 링크
- 서버 저장·회원 기능 (개인정보 처리방침과 함께)

## 12. 만드는 방법 (클로드가 끝까지 만들 때 기준)
- 분위기: 깔끔한 (하얀 바탕, 정돈된 업무 도구 느낌, 보고서에 넣기 좋게) · 참고 디자인: 없음 — 클로드가 정함
- 문장 해석: **규칙 + 도우미 화면.** 입력한 한글 문장은 브라우저 안에서 정해진 문장 규칙으로 해석한다. 외부 AI나 서버로 보내지 않는다 (저장·전송 안 함 원칙 때문)
  - 알아듣지 못한 문장은 입력칸 옆에 표시하고, 어떻게 쓰면 되는지 예시를 보여 준다
  - 해석이 갈리는 표현(가깝다, 사이가 안 좋다, 연락이 뜸하다, 할머니의 친가/외가, 헤어졌다 등)은 선을 미리 긋지 않고 '골라 주세요' 카드로 묻는다
  - 직접 고치기: 가계도에서 사람·선을 눌러 모든 항목을 고치고, 누구 기준으로든 부모·형제·배우자·자녀·반려동물을 더하고, 끌어서 옮기고, 되돌린다. 직접 고친 뒤에는 문장에서 새로 나온 내용만 더한다
- 가계도 기호: McGoldrick 계열 임상 관례를 기본으로(남성 □, 여성 ○, 성별 모름 ◇, 내담자 이중 테두리, 사망 X, 결혼·동거·별거·이혼, 재혼, 이복형제, 입양 파선·위탁 점선·친자 미상, 쌍둥이, 임신·유산·사산, 반려동물, 함께 사는 가족 경계, 세대 번호, 정서적 관계 13종). 기관마다 다른 기호는 글자를 함께 붙이고 범례에 적는다. 기관 지침이 우선이라고 안내한다
- 내려받기: 이미지(PNG)와 PDF
- 문의 저장: 아니오 → Supabase·/admin 없음
- 회원가입: 이번엔 아니요
- 배포: GitHub 공개 저장소 + Vercel

## 13. 만드는 순서 (클로드가 처음부터 끝까지 한 번에)
1. 스타일(색·글꼴)을 분위기에 맞게 정하고 첫 화면부터 만든다
2. 문장 규칙과 가상 사례 예시를 정하고, 입력칸 → 못 알아들은 문장 표시 → 도우미 화면 → 가계도 그리기 → 이미지·PDF 내려받기를 만든다
3. GitHub 공개 저장소에 올리고 Vercel로 배포해 내 주소를 만든다
4. 다 만든 뒤 한 번에 보고: 내 사이트 주소 · 확인 방법 · 사용자가 할 일
- 사용자가 직접 할 일(이때만 멈춤): 로그인, 결제
